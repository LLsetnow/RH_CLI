# 工作流快捷提交与任务费用展示设计

## 目标

为本地 RH Workflow Desk 增加工作流快捷提交操作，并在任务队列和任务详情中展示 RunningHub 返回的本次任务消耗。

## 范围

本次只涉及 `web/` 前端展示与现有任务费用字段的使用：

- 主工作流页面支持 `Ctrl + Enter` 提交当前工作流。
- 快捷提交复用现有“加入任务队列”按钮的全部校验和请求逻辑。
- 任务队列卡片显示已完成任务的 RH 币或金额消耗。
- 任务详情弹窗同步显示费用。
- 不增加费用预估或额外远程查询。

已有的任务调度、远程轮询、输入文件路径处理和提示词工坊页面保持不变。

## 方案

### 快捷提交

在主工作流页面的文档级 `keydown` 事件中识别 `Ctrl + Enter`：

- 仅匹配 `event.ctrlKey && event.key === "Enter"`。
- 忽略输入法组合状态，避免中文输入过程中误触发。
- 调用现有 `submitTask()`，因此继续执行工作流、RunningHub workflowId、文件输入和重复提交校验。
- 调用时阻止浏览器默认行为；在提示词 `textarea` 中不会插入换行。
- 仅 `app.js` 主工作流页面绑定，提示词工坊页面不受影响。
- 在提交区域增加轻量提示 `Ctrl + Enter 快捷提交`，让操作可发现。

### 费用展示

任务完成时，后端已经从 RunningHub 输出中的 `consumeCoins` 或 `consumeMoney` 保存 `cost_type` 和 `cost`。前端新增统一格式化函数：

- `cost_type === "coins"`：`消耗 {cost} RH 币`
- `cost_type === "money"`：按任务凭据站点显示 `消耗 ¥{cost}` 或 `消耗 ${cost}`
- 任务尚未完成或没有费用字段：显示“费用待返回”或保持空白，不猜测金额

任务队列卡片在任务底部显示费用标签；任务详情弹窗的元信息区域显示同样的费用信息。旧任务没有费用字段时兼容展示，不修改数据库历史数据。

## 数据流

```text
Ctrl + Enter / 点击加入任务队列
  -> submitTask()
  -> 现有本地任务创建与远程执行
  -> outputs 返回 consumeCoins / consumeMoney
  -> 后端保存 cost_type + cost
  -> /api/state 返回任务费用
  -> 队列卡片和详情弹窗格式化展示
```

费用展示只消费已经存在的本地任务数据，不触发新的 RunningHub API 请求，也不影响费用记录和产物下载。

## 错误与边界

- 快捷键触发时缺少任何必填输入，使用现有错误提示并停止提交。
- 正在提交时，沿用现有按钮禁用状态，避免重复创建任务。
- `cost` 为 `0` 时显示明确的零值，不把零值当作缺失。
- `cost` 为空、类型未知或任务失败时不显示虚假费用。
- 任务凭据已删除时，金额类型使用已保存的 `key_site`；没有站点信息时显示“金额 {cost}”。
- 不记录或展示 API Key 等敏感信息。

## 验证

- JavaScript 语法检查通过。
- 静态检查确认快捷键只绑定主页面，并调用现有 `submitTask()`。
- 使用带 `coins`、`money`、零值和缺失费用的任务数据检查格式化结果。
- 运行现有 Web 与 workflow 测试，确认任务费用字段、输出产物和现有提交逻辑不回归。
- 启动 Electron 开发版检查页面资源和本地健康检查；不发起真实远程任务。
