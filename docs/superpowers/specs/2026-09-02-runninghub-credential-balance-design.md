# RunningHub Web 凭据余额查询设计

## 目标

在 RH_CLI 的本地 Web 应用中，让 RunningHub 凭据在添加或完整检测时自动查询余额，并在凭据卡片上展示余额；同时提供独立的“刷新余额”操作。凭据卡片的“检测”和“删除”按钮一并调整为清晰、统一的操作样式。

## 范围

本次只涉及 `web/` 本地 Web 应用及其测试：

- 使用已有的 RunningHub `accountStatus` 接口，不引入新的远程服务或依赖。
- 保留现有凭据存储格式，并向前兼容没有余额查询时间字段的旧记录。
- 不展示或写入日志输出完整 API Key。
- 不改变任务调度、工作流提交和 CLI 终端凭据行为。

## 方案

### 后端接口

在 `web/app.py` 中抽出共享的账户状态查询逻辑，按凭据的 `site` 选择 `ACCOUNT_STATUS_URL_CN` 或 `ACCOUNT_STATUS_URL_AI`，沿用现有代理和超时配置。

保留现有接口：

`POST /api/keys/:id/check`

- 校验 API Key。
- 更新认证状态、状态消息、账户类型、并发容量以及余额。
- 添加凭据继续通过此完整检测完成首次验证和余额查询。

新增接口：

`POST /api/keys/:id/balance`

- 只查询并更新 `remainMoney`、`remainCoins`、货币符号和余额查询时间。
- 成功返回脱敏后的公开凭据对象。
- 失败返回现有标准错误，不覆盖已有余额，也不改变认证状态、账户类型、并发容量和完整检测时间。

凭据记录新增 `balance_checked_at`，以毫秒时间戳记录最近一次成功余额查询。旧记录缺少此字段时按 `0` 处理。现有 `checked_at` 继续表示完整凭据检测时间。公开对象包含 `balance_checked_at`，但不包含 `api_key`。

### Web 界面

凭据卡片在运行/并发和账户类型信息附近增加余额行：

`余额 ¥12.34 · 150 RH 币`

AI 站点使用 `$` 符号。没有成功查询过时显示“余额未查询”；余额为零时显示具体的零值，同时保留“无余额”状态。成功查询后显示相对更新时间，例如“余额更新于刚刚”或“余额更新于 3 分钟前”。

操作区统一为三个紧凑按钮：

- “检测”：中性描边按钮，执行完整凭据检测。
- “刷新余额”：青绿色弱填充或描边按钮，执行独立余额查询。
- “删除”：低对比度红色文字或弱红色描边按钮，悬停时增强危险提示。

三个按钮保持统一高度、圆角、字体和间距；窄屏时允许换行。查询期间只禁用当前点击的按钮，并显示进行中状态。查询失败时弹出错误提示并保留卡片已有余额。添加成功提示明确包含余额已更新的信息。

### 数据流

```text
添加凭据 ─┐
完整检测 ─┴─> accountStatus ─> 更新认证/账户/余额字段 ─> 渲染凭据卡片

刷新余额 ───> accountStatus ─> 仅更新余额字段 ─────────> 渲染凭据卡片
```

## 错误处理与安全

- 找不到凭据仍返回 `KEY_NOT_FOUND`。
- RunningHub 非成功响应沿用当前错误分类和脱敏机制。
- 余额刷新网络或接口失败不把凭据变成 `error`，也不清空最后一次成功余额。
- API Key 只保存在本地凭据文件，公开 API 响应继续使用脱敏值。
- 不为余额添加后台定时轮询，避免无必要的远程请求；用户通过添加、检测或手动刷新触发查询。

## 验证

后端测试覆盖：

- 完整检测成功时保存现金余额、RH 币余额和两个时间字段。
- 独立余额刷新成功时只更新余额相关字段。
- 余额为零时状态为 `no_balance`，但仍展示零值。
- 独立刷新失败时旧余额和认证状态保持不变。
- 公开凭据对象不包含完整 API Key，并兼容旧记录。

前端和集成验证覆盖：

- 两个查询按钮调用各自正确的接口，并在请求期间禁用当前按钮。
- 查询成功后刷新卡片内容；失败时显示错误提示。
- 余额未查询、零余额、中文站点和 AI 站点的展示格式正确。
- 运行现有 Python 测试、JavaScript 语法检查，并启动本地 Web 服务验证健康检查和路由可用性；不使用真实 API Key 发起测试请求。

## 实现文件

- `web/app.py`：余额字段默认值、共享 RunningHub 账户查询、余额刷新方法和公开数据。
- `web/server.py`：新增余额刷新路由。
- `web/static/app.js`：余额渲染、相对时间、刷新按钮和加载/错误状态。
- `web/static/app.css`：余额行和凭据操作按钮的统一视觉样式。
- `web/tests/test_app.py`：余额查询及失败保留数据的单元测试。
